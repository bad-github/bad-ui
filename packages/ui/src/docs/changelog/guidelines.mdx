# 更新日志记录规范

## 目录与菜单

每次发布在 `src/docs/changelog/` 下新增 `YYYY-MM-DD.mdx`，并设置对应标题：

```mdx
import { Meta } from '@storybook/addon-docs/blocks';

<Meta title="Development/Changelog/YYYY-MM-DD" />

# YYYY-MM-DD · 本次发布主题

## 新增

- 记录本次新增的组件、示例或功能。

## 修复

- 记录本次问题修复。

## 发布说明

- 填写实际部署状态；涉及 npm 发版时补充确切版本及升级注意事项。
```

同一天的补充更新合并到同一日期页面；跨日期发布新增页面。菜单由文档标题自动生成，无需手动登记。

## 内容要求

- 日期页面只记录对应发布的更新内容、修复、发布状态和升级注意事项，不包含记录规范或编写模板。
- 按需使用“新增”“改进”“修复”“发布说明”等章节，没有内容的章节直接省略。
- 写清具体组件、变化及对使用者的影响，避免只写“优化体验”等泛泛描述。
- 仅记录已经实现或验证的事实；尚未上线时标明“待部署”，不要将发布准备写成已成功发布。
- npm 版本与 Storybook 部署分别记录；涉及包发布时填写实际版本号，不将示例版本当成已发布版本。
- 部署完成后更新对应日期页面的状态与线上地址；已发布记录中的事实错误可直接修正。
- 后续计划放在独立计划文档中，不混入日期更新日志。

## 排序

Changelog 下的日期页面按 `YYYY-MM-DD` 倒序排列，最新日期在前；其他分组继续沿用现有字母排序规则。
